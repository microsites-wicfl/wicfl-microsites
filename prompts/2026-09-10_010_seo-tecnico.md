## Contexto

Este repo genera múltiples microsites de seguros de nicho desde un único template Astro
compartido (`packages/template`), uno por cada `sites/<slug>/`. `npm run build:site --
<site-directory>` construye un sitio: valida su `site.config.json` contra el schema, y llama a
`astro build` pasándole ese config y el contenido markdown del sitio vía las variables de
entorno `WICFL_SITE_CONFIG`/`WICFL_SITE_CONTENT`, que `packages/template/src/lib/site-data.mjs`
lee y expone como el objeto `site` (import `{ site } from "../lib/site-data.mjs"`).

Hoy el template no tiene ningún SEO técnico: ninguna página trae `<link rel="canonical">`, no
existe `robots.txt` ni `sitemap.xml`, y no hay datos estructurados (schema.org) en ninguna
página. Esto bloquea el launch del sitio #1 el 9 de octubre, aunque no bloquea nada de lo que
Pavel hace hoy (Fase 3, escribir contenido).

El schema (`packages/config-schema/site.config.schema.json`) ya tiene el campo que hace falta:
`domain` — "Apex production domain, without protocol, path, or www." Para el sitio real
(`sites/stuart-homeowners`) hoy vale `stuarthomeownersinsurance.com`. Los sitios fixture
(`sites/_*`, usados por CI) pueden tener un dominio de prueba o placeholder; no valides ni
rechaces eso aquí, ese control ya existe en otro lado (`scripts/check-production-config.mjs`,
W-103) y corre en un paso distinto del pipeline, antes de un deploy real. Este prompt no lo toca.

Las páginas del sitio se generan en dos archivos: `packages/template/src/pages/index.astro`
(sirve siempre en `/`) y `packages/template/src/pages/[...slug].astro` (todas las demás,
vía `getStaticPaths` sobre la content collection `pages`). Ambos ya importan
`routeForPageId(id)` de `site-data.mjs`, que devuelve la ruta real de una página (`"/"` para el
home, `"/high-value-home-insurance/"` para una interior, con el prefijo de idioma correcto si es
un locale alternativo — ver W-022). Usa esa función, no reinventes el cálculo de rutas.

## Objetivo

Cuando termines, cualquier sitio construido con `npm run build:site -- <site-directory>` debe
traer, sin que Pavel tenga que hacer nada:

1. **Canonical URL** correcto en cada página, calculado a partir de `site.domain` y la ruta real
   de esa página.
2. **`robots.txt`** en la raíz del sitio construido, permitiendo todo y apuntando a su sitemap.
3. **`sitemap.xml`** en la raíz del sitio construido, listando cada página real del sitio con su
   URL absoluta.
4. **Datos estructurados schema.org** (`InsuranceAgency`) en cada página, con el NAP real del
   sitio (nombre, teléfono, email, dirección) tomado del config.

## Pasos

1. Lee `packages/template/src/layouts/BaseLayout.astro`, `packages/template/src/pages/
   index.astro`, `packages/template/src/pages/[...slug].astro` y `packages/template/src/lib/
   site-data.mjs` completos antes de tocar nada, para entender el flujo real de props y rutas.
2. Agrega a `BaseLayout.astro` un `<link rel="canonical" href="...">` en el `<head>`, construido
   como `https://${site.domain}${ruta de esta página}`. Necesitarás pasarle la ruta de la página
   como prop nueva desde `index.astro` (siempre `"/"`) y desde `[...slug].astro` (con
   `routeForPageId(page.id)`, que esos archivos ya importan).
3. Crea `packages/template/src/pages/robots.txt.ts` (endpoint Astro, no archivo estático) que
   devuelva texto plano:
   ```
   User-agent: *
   Allow: /

   Sitemap: https://<site.domain>/sitemap.xml
   ```
4. Crea `packages/template/src/pages/sitemap.xml.ts` (endpoint Astro) que itere la content
   collection `pages` completa (`getCollection("pages")`) y devuelva XML válido según el
   protocolo de sitemaps.org (`<urlset><url><loc>...</loc></url>...</urlset>`), una entrada por
   página, cada `<loc>` con la URL absoluta real (`https://${site.domain}${routeForPageId(id)}`).
   No inventes `<lastmod>`: no hay fechas reales de modificación que reportar todavía, mejor
   omitir el campo que mentir con una fecha de build.
5. Agrega a `BaseLayout.astro` un bloque `<script type="application/ld+json">` en el `<head>`
   con `@context: "https://schema.org"`, `@type: "InsuranceAgency"`, y como mínimo `name`
   (`site.brand.name`), `telephone` (`site.contact.trackingPhone`), `email`
   (`site.contact.email`), `address` (`PostalAddress` armado desde `site.contact.address`), y
   `areaServed` si `site.geo.serviceArea` existe. Mismo bloque en cada página: la consistencia de
   NAP en todas las páginas es una señal positiva por sí misma, no hace falta limitarlo al home.
6. Construye `stuart-homeowners` (`npm run build:site -- stuart-homeowners`) y también algún
   fixture bilingüe existente bajo `sites/_*` si lo hay, para confirmar que el ruteo con prefijo
   de idioma (W-022) no rompe el canonical ni el sitemap.
7. Corre `npm run check`. Debe seguir en verde.
